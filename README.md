# 종목 탐색기 (조건별 리스트 + 중복 표시 + 사후 성과 검증)

매일 아침 장 시작 전(07:45 KST), **코스피/코스닥 시가총액 상위 50%**를 나눠서 아래 6개 지표를 각각
판단하고, 몇 개 지표가 동시에 신호를 내는지로 종목을 정렬합니다.
그렇게 뽑힌 픽들이 **1주일/1개월 후 실제로 어떻게 됐는지 자동으로 추적**합니다.

1. RSI(14) 30 이하 (과매도) 중 가장 과매도인 상위권
2. 이격도(20일선)가 가장 낮은(=주가가 평균선에서 가장 많이 아래로 벌어진) 하위권
3. 거래대금(종가×거래량) 상위권
4. 거래량 급증배수(당일 거래량 ÷ 20일 평균 거래량) 상위권
5. 이동평균선 정배열 (5일선 > 20일선 > 60일선) 중 단기/장기 이평 격차가 큰 상위권
6. 공매도 거래량 감소 (최근 3일 평균이 그 이전 3일 평균보다 낮음, 매도 압력 완화 신호)

이 6개 중 몇 개가 겹치는지에 따라 **2개 이상 / 3개 이상 / 4개 이상 / 5개 이상 / 6개(전부 일치)**
등급으로 나눠서 표시합니다. 이 중 이격도/거래대금/거래량급증은 "방향(상승/하락)을 구분하지 못하는"
지표라, 이 3개끼리만 겹치는 조합은 별도의 **"하락 주의"** 리스트로 분리해서 표시합니다.

**시가총액 상위 50%를 병렬로 스캔**하되, 공매도 조회는 나머지 5개 지표에서 이미 상위권으로 뽑힌
후보 종목에 대해서만 수행해서 전체 실행 시간을 줄입니다.

> ⚠️ 이 도구는 조건에 맞는 종목을 기계적으로 찾아주는 스크리닝 도구이며,
> 매수/매도를 추천하는 것이 아닙니다. 투자 판단과 책임은 본인에게 있습니다.

## 2. 셋업

1. GitHub에 새/기존 저장소 → 이 폴더 파일 전체 업로드
2. `.github/workflows/*.yml`이 안 올라갔다면, **Add file → Create new file**로
   경로를 직접 입력해서 만들기 (드래그 업로드 시 숨김 폴더가 자주 빠집니다)
3. **Settings → Pages** → Branch `main`, 폴더 `/docs` 선택 → Save
4. **Actions → Daily Stock Screening → Run workflow**
5. 완료되면 아이폰 사파리로 `https://<내계정>.github.io/<저장소이름>/` 접속 →
   공유 버튼(⬆️) → 홈 화면에 추가

## 3. 사후 성과 검증은 어떻게 동작하나요

- `main.py`가 매일 "2개 이상 중복" 픽들을 `docs/history.json`에 날짜별로 누적 기록합니다.
- 같은 워크플로우 안에서 바로 이어서 `evaluate_picks.py`가 실행되어,
  **기록된 지 7일(1주) 또는 30일(1개월)이 지난 픽**들의 현재가를 조회해
  수익률을 계산하고 `docs/history.json`에 채워 넣습니다.
- 그 결과를 집계해 `docs/performance_summary.json`에 저장하고,
  화면 맨 위 "지난 픽 사후 성과" 카드에 평균 수익률/승률로 표시합니다.
- "1주/1개월"은 실제 거래일이 아니라 **달력 기준 날짜**로 계산합니다 (휴장일 캘린더 없이도
  안정적으로 동작하게 하기 위함).
- 데이터가 쌓이기까지 **최소 1주일 이상** 걸립니다 (그 전까지는 카드에 "데이터 쌓는 중"이라고 표시됩니다).

## 4. 스캔 범위 및 실행 시간

- **코스피/코스닥 시가총액 상위 50%**를 스캔합니다. 전체 상장 종목 목록을 먼저 가져온 뒤
  (`TOP_N_PER_MARKET=3000`으로 사실상 전체 목록 확보), 시가총액 내림차순으로 정렬된 그 목록에서
  앞쪽 절반만 잘라서 스캔합니다 (`SCAN_PERCENTAGE = 0.5`).
- 60일 이동평균 계산을 위해 종목당 시세를 넉넉히(70일치) 가져옵니다.
- 종목이 많아진 만큼, 시세 조회는 **동시에 여러 종목씩 병렬로**(`SCAN_WORKERS`, 기본 8개) 처리합니다.
  공매도 조회는 나머지 5개 지표에서 이미 상위권으로 뽑힌 후보 종목에 대해서만 수행해서
  불필요한 요청을 줄입니다.
- **실행 시간은 아직 실측 전이라 정확히 알 수 없습니다.** 상위 150개씩(총 300개)만 스캔했을 때는
  20~30분 정도였습니다. 시가총액 상위 50%(코스피+코스닥 합쳐 1000개 이상 추정)로 늘리면
  병렬 처리를 감안해도 그보다는 오래 걸릴 가능성이 높습니다. `.github/workflows/daily-screen.yml`의
  cron은 **한국시간 07:45**에 시작하도록 되어 있는데, 실행 시간이 너무 길어서 장 시작(09:00) 전에
  안 끝나면:
  - `SCAN_WORKERS` 값을 늘려서 병렬도를 높이거나
  - cron 시작 시각을 더 앞당기거나 (예: 전일 장마감 직후로)
  - `SCAN_PERCENTAGE` 값을 더 줄여서 스캔 범위를 좁히는
  조정이 필요할 수 있습니다. 처음 몇 번은 꼭 실제 소요 시간을 확인해보세요.
- **매매 타이밍 전략**: 전일 종가 기준으로 스크리닝하고, **장 시작(09:00) 동시호가/시가에 매수**한
  뒤 목표 수익률에 맞춰 매도 주문을 걸어두는 방식을 전제로 설계했습니다.

## 5. 장중 가격 갱신

전체 스크리닝과는 별도로, 이미 뽑힌 종목들의 **현재가/등락률**만 장중(09:00~15:45) 5분마다
`update_prices.py`가 갱신해 `docs/live.json`에 저장합니다. `docs/index.html`이 이 파일을
읽어서 화면에 표시합니다 (같은 사이트 내 파일이라 브라우저 CORS 제한이 없음).

## 6. 조건 값 조정

`main.py` 상단의 설정값으로 조정할 수 있습니다:

```python
RSI_THRESHOLD = 30            # RSI 몇 이하를 "과매도"로 볼지
RSI_TOP_N = 10
DISPARITY_MA_PERIOD = 20
DISPARITY_TOP_N = 10
TURNOVER_TOP_N = 10
VOLUME_SURGE_TOP_N = 10
VOLUME_SURGE_MA_PERIOD = 20
MA_SHORT, MA_MID, MA_LONG = 5, 20, 60   # 정배열 판단 기준 이동평균선
MA_ALIGN_TOP_N = 10
SHORT_SELL_HISTORY_DAYS = 10
SHORT_SELL_RECENT_N = 3        # 공매도 거래량 감소 판정 시 비교할 최근/이전 구간 길이
SHORT_SELL_TOP_N = 10
TOP_N_PER_MARKET = 3000        # 시장 전체 목록을 가져오기 위한 값 (실제 상장 종목 수보다 크게 설정)
SCAN_PERCENTAGE = 0.5          # 그중 시가총액 상위 몇 %만 실제로 스캔할지 (0.5 = 상위 50%)
HALT_CHECK_DAYS = 3            # 최근 이 기간 중 거래량 0인 날이 있으면 거래정지로 보고 제외
LIST_DISPLAY_TOP_N = 20        # 화면에 보여줄 각 지표별 리스트 최대 개수
SCAN_WORKERS = 8               # 시세/공매도 조회 동시 요청 수 (너무 높이면 차단 위험)
HISTORY_MAX_ENTRIES = 200      # history.json에 보관할 최대 일수
```

**거래정지 종목 필터링**: 최근 `HALT_CHECK_DAYS`일 중 단 하루라도 거래량이 0이면 그 종목은
스캔에서 완전히 제외됩니다. 거래정지 중엔 가격이 안 움직여 지표가 왜곡되고,
거래 재개 시 액면분할·감자 등으로 가격이 급변해 "폭락"처럼 잘못 잡히는 문제가 있었기 때문입니다
(실제 사례: 거래정지 상태였던 종목이 재개되며 액면분할로 종가가 반토막 나 -59% 폭락처럼 표시된 적 있음).

중복(overlap) 판정 기준 지표는 `main.py`의 `OVERLAP_TAGS` 리스트로 조정할 수 있습니다
(현재는 6개: rsi, disparity, turnover, volume_surge, ma_align, short_sell).

`evaluate_picks.py` 상단의 `HORIZONS = {"1w": 7, "1m": 30}` 값을 바꾸면
평가 시점(며칠 후 수익률을 볼지)을 조정할 수 있습니다.

## 7. 화면 표시 관련 참고

- 6개 지표 중 몇 개가 겹치는지에 따라 **2개 이상 / 3개 이상 / 4개 이상 / 5개 이상 / 6개(전부 일치)**
  등급으로 나눠서 표시합니다. 겹치는 개수가 많을수록 위쪽(더 눈에 띄는 스타일)에 표시됩니다.
- 하단의 이격도/거래대금/거래량급증/정배열 개별 리스트는 화면에서 숨겨져 있습니다
  (중복 판정 계산에는 계속 사용됩니다). `docs/index.html`의 `groupDefs` 배열에서 주석을
  해제하면 다시 보이게 할 수 있습니다.
- "N개 이상 중복" 리스트는 우측에 전일 대비 등락률을 크게 표시하며,
  장중에는 5분마다 실시간 등락률로 자동 갱신됩니다.
- "2개 이상 중복" 종목 중, 방향(상승/하락)을 구분하지 못하는 지표끼리만 겹친 경우
  (이격도+거래량급증 / 거래대금+거래량급증 / 이격도+RSI) 는 급락 당일에도 걸릴 수 있어서
  일반 중복 리스트에서 빼고, 화면 최하단의 "⚠️ 2개 이상 중복이지만 하락 주의" 리스트로 따로 표시합니다.
  기준 조합은 `main.py`의 `RISKY_COMBOS`에서 조정할 수 있습니다.
- 상단에 코스피/코스닥 지수 현재가 + 최근 추이 그래프가 표시됩니다 (장중 5분 간격 데이터 기준).
- 지수 카드에 **외인/기관/개인 시장 전체 순매매(억원)**도 함께 표시됩니다. 이 데이터는 네이버가 아닌
  한국경제(markets.hankyung.com) 페이지에서 가져오는 **실험적 기능**이라, 페이지 구조가 바뀌면
  조용히 실패하고 그 부분만 안 보일 수 있습니다 (다른 기능에는 영향 없음).

## 8. 백테스트 (과거 검증)

"6개 지표 중 2개 이상 중복" 조건이 실제로 상승 신호였는지, 과거 데이터로 검증할 수 있습니다.

- **Actions → Backtest (과거 검증) → Run workflow**로 수동 실행 (자동 스케줄 없음)
- `top_n`(시장당 평가 종목 수), `eval_days`(평가할 과거 거래일 수)를 입력받아 실행
- 결과는 `docs/backtest_result.json`에 저장되고, 실행 로그에도 요약이 출력됩니다:
  픽으로 뽑힌 종목들의 1주/1개월 후 평균 수익률 vs 그날 스캔된 전체 종목 평균 수익률(베이스라인) 비교
- **한계**:
  - 종목 유니버스는 "오늘 기준" 시가총액 상위 N이라 과거 시점 실제 상위 N과 다를 수 있음(생존편향 가능)
  - 공매도 거래량 감소 조건은 과거 일별 데이터를 안정적으로 모으기 어려워 백테스트에서 제외됨
    (실질적으로 RSI/이격도/거래대금/거래량급증/정배열 5개 신호 기준 검증이 됨)
- 종목 수 x 평가 기간이 클수록 네이버 요청이 많아져 오래 걸리므로, 처음엔 기본값(40종목/40거래일)으로
  먼저 실행해보고 필요시 늘릴 것
